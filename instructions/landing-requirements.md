## Рекомендации по реализации

- Next.js App Router, TypeScript, ESLint, локальные шрифты и исходные стили как стартовая база; не добавлять Tailwind без потребности, поскольку готовая стилистика уже написана в CSS.
- Использовать только нужные слои Feature-Sliced Design: `app`, `pages`, `widgets`, `features`, `entities`, `shared`. Для одного лендинга не создавать пустые слои и искусственные сущности. В Next.js маршруты разместить в корневой папке `app/`, а слой страниц FSD назвать `src/_pages/`, чтобы он не конфликтовал со специальной папкой Next.js.
- Разделить JSON по смыслу: тексты страницы, проекты, FAQ, SEO/контакты. Файлы изображений хранить отдельно, а в JSON указывать относительные имена или пути. Данные проверять типами/схемой на этапе сборки.
- Сохранять серверный рендеринг статических разделов; клиентский код ограничить интерактивными элементами.
- Проверять перенос не только сборкой, но и unit-тестами логики формы и e2e-сценариями формы, модальных окон, навигации, мобильной ширины и доступности управления с клавиатуры.

- `npm audit --omit=dev` не нашёл известных уязвимостей production-зависимостей. Полная проверка выявила пять предупреждений высокой степени в цепочке `eslint-config-next → fast-glob → micromatch → braces` среди инструментов разработки; исправленной версии `braces` в npm на момент проверки нет. Не снижать версию Next.js только ради обхода предупреждения без отдельной оценки.
- На этом этапе прототип ещё не был перенесён в Next.js; перенос зафиксирован отдельным вторым этапом ниже.
